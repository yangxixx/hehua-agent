## 架构（v1，Python 包 `agentx`，借鉴 BreachWeave 已验证模式并简化）

核心结论：解题体 = coding-agent 式强工具循环（bash+文件+渗透工具），编排/预算/生命周期全部外置为确定性代码（不信模型自述）。

```
src agent/
├── pyproject.toml / .env.example / README.md
├── agentx/
│   ├── config.py            # env、预算常量、模式探测 local|hosted|mock
│   ├── gateway.py           # rewrite_for_gateway(): +".tsecbench.gw"、https→http、18域白名单校验
│   ├── llm/                 # httpx 手写 OpenAI 兼容客户端(重试/退避/tool-calls/usage)；deepseek→qwen failover；token 成本分桶统计
│   ├── orchestrate/         # runner(主循环+finally关容器) / scheduler(排序+分级限时+R2二次扫描) /
│   │                        # lifecycle(start重试、max-active、孤儿清扫) / state(断点续跑 state.json)
│   ├── core/                # agent(主循环+看门狗) / tools(9工具) / sandbox(bash超时kill+输出落盘) /
│   │                        # context(截断+滚动摘要) / memory(notes: idea/fact/failure/todo)
│   ├── prompts/             # system.md + 6 维 playbook（web/killchain 做深，其余打底）+ compact.md
│   ├── metrics/             # events.jsonl + report.py(发现率/耗时/token/人机对比 → BSRC 材料)
│   └── cli.py               # python -m agentx {run|smoke|report|resume}
├── docker/Dockerfile + entrypoint.sh   # python:3.12-slim + 精选工具 ≤3GB
├── tests/ + mock/(假平台含sqli/命令注入真靶 + 脚本化假LLM，离线全链路回归)
```

**工具集（9）**：bash(≤300s、输出落盘回传 head+tail≤8KB)、http_request、read_file、write_file、list_dir、grep、notes、submit_flag(回传剩余 flag 数驱动续攻)、finish(唯一合法退出)。

## 核心能力覆盖（针对赛题形态明确强化）

**1. 目录扫描 + 爬虫（深层目录里的洞）**
- 爬虫：烘焙 `katana`（projectdiscovery 爬虫，~30MB）+ 自研 `scripts/crawl.py`（标准库递归抓链、解析 robots.txt / sitemap.xml / JS 内嵌路由、提取表单）；system prompt 硬纪律"先爬虫收集完再打点，每个响应体检查新链接/新参数"（BreachWeave 实测有效条款）。
- 目录扫描：ffuf / gobuster + 精选 seclists 字典（常见目录/API 路径/备份文件/管理后台/.git 泄露）烘焙进镜像；侦察后标准动作，发现 403/401 目录记 notes 待绕过。
- 路由/参数 fuzz：数字 ID ±1~1000 脚本化循环（照 BreachWeave 条款），隐藏参数爆破（参数名字典）。

**2. 自主注册 + 越权测试（逻辑洞主力，SRC 高危大头）**
- web playbook 强制流程：用 http_request/curl **自主注册 ≥2 个账号**（处理注册表单、常见弱校验；遇短信/邮件验证码边缘情况记 failure 换路），会话/cookie/token 存 notes。
- 横向越权：A/B 账号互访对方资源接口（订单/个人信息/消息/文件），比对响应差异判定 IDOR。
- 纵向越权：低权限会话直访管理路由、role/uid 参数篡改、JWT 篡改（flask-unsign/pyjwt 已烘焙）。
- 未授权：未登录态直接打需鉴权接口（API/小程序风格，匹配用户既有渗透经验）。

**3. 漏扫（自动化扫描器打底 + LLM 补逻辑洞）**
- nuclei（精选 http/vulnerabilities 模板烘焙、`-c 8` 限并发）侦察后标准扫描，命中即转人工式深打。
- sqlmap `--batch` 确认 SQLi；whatweb 指纹→known-product 漏洞检索。
- 扫描器扫不出的（越权/业务逻辑/反序列化链）由 LLM agentic 审计补位——这是与传统漏扫的差异点，也是 BSRC 材料叙事。

**防死循环四件套**：工具硬超时；同命令连 3 次→注入换思路；连 8 步无进展→注入换方向清单；预算软限提醒+硬限强制 finish。

**调度**：净预算 315min；R1 通扫分级限时（easy 4m/med 8m/hard 15m/killchain 40m）；R2 只打"有进展未出旗/多 flag 拿部分/被跳过"；优先级=分值×维度权重÷难度；串行+预启动伪并发；hint 仅耗≥70%预算且有推进中 idea 时用。

**镜像**：nmap/sqlmap/ffuf/gobuster/katana/nuclei(+精选模板)/hydra/pwntools/gdb + 精选 seclists 字典 + scripts/crawl.py 等；弃 chromium/AD 全家桶/hashcat（v1 不打）。

## 验证（三层）

1. 离线：`smoke --mode mock`（假平台+假LLM，3min）+ pytest（网关 18 域、截断、调度预算、续跑、看门狗）——每天跑。
2. 真实：XBOW 本地模式 3→10→40→104 题放量（绝对分只做回归基线，实战锚定 deepseek 系 60-70%）。
3. 预实战：d8 本地 docker run mock；d9 平台 360min dry-run。验收：抽样成功率≥60%、单题均时≤6min、零容器泄漏。

## 关键风险与对策（Top 5）

1. Win11 Home 无 Docker → `wsl --install`+BIOS VT-x；备选 GitHub Actions build+push；最差借机器只 build。
2. VPN 客户端不稳 → agent 整体搬进 WSL2 跑。
3. 网关改写格式存疑 → d2 单测锁假设；d9 进沙箱先 curl 逐域验证。
4. 单题死循环拖垮预算 → 四件套+分级限时+两轮制（R1 数据调 R2 参数）。
5. DeepSeek 限流 → qwen failover + 429 退避 + token 软上限。
